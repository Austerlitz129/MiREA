# MiREA Entity Interaction and Evidence Page Generation

## Overview

This directory contains the original scripts used to generate entity-interaction network files and literature-evidence detail pages for the MiREA web platform.

The workflow operates on disease-specific `data` and `sp` tables. Several intermediate files were manually prepared in spreadsheets before running the scripts. The original Python filenames and internal code are preserved.

The Django `views.py` file is not included here. Website rendering and Django integration are handled separately in the web-platform code.

## Directory structure

```text
MiREA_entity_interaction_scripts/
├── README.md
├── requirements.txt
├── GuanL.py
├── GuanLscript.py
├── details.py
└── details_html.py
```

```text
disease-specific data.csv / sp.csv
            │
            ├── manually prepare <prefix>GuanL.txt
            │       └── represent missing values with @
            │
            ├── manually prepare Pmids.txt
            ├── manually prepare detail.txt
            ├── manually prepare id.txt
            └── manually prepare html_gm.txt

<prefix>GuanL.txt
    │
    └── GuanL.py
            ├── <prefix>GL1/*.txt     node fragments
            └── <prefix>GL2/*.txt     relationship fragments
                    │
                    └── GuanLscript.py

    │
    └── details.py
            └── DT/*.text
                    │
                    └── details_html.py + html_gm.txt
                            └── details/*.html
```

## Installation

Python 3.9 or later is recommended.

```bash
python -m pip install -r requirements.txt
```

The evidence-detail workflow retrieves PubMed metadata through NCBI Entrez and therefore requires an internet connection.

## 1. `GuanL.py`: generate entity-interaction fragments

### Purpose

`GuanL.py` reads a disease-specific tab-delimited interaction file and generates separate node and relationship fragments for each interaction record. These fragments are subsequently converted into ECharts JavaScript files.

### Manually prepared input

The input filename must follow this pattern:

```text
<prefix>GuanL.txt
```

For example:

```text
gcGuanL.txt
```

The file is manually derived from the corresponding disease-specific `data` table. It contains nine tab-delimited columns without a header:

| Column | Content |
|---|---|
| 1 | Interaction ID |
| 2 | Gene |
| 3 | Microbiota |
| 4 | Jaccard coefficient |
| 5 | Overlap coefficient |
| 6 | Metabolite |
| 7 | Immune cell |
| 8 | Enrichment P value |
| 9 | Metabolite change or direction |

Missing fields must be represented by:

```text
@
```

### Usage

```bash
python GuanL.py --file gc --directory /path/to/input_directory
```

Short options are also supported:

```bash
python GuanL.py -f gc -d /path/to/input_directory
```

### Output

For a prefix such as `gc`, the script creates:

```text
gcGL1/    node fragments
gcGL2/    relationship fragments
```

The network contains four entity categories:

- Gene
- Microbiota
- Metabolite
- Immune cell

The generated relationships include gene–microbiota, gene–metabolite, gene–immune-cell, and microbiota–metabolite links. The original visualization rules use the Overlap coefficient and immune-cell enrichment P value to control selected edge widths. Metabolite-change information is stored as a relationship label.

## 2. `GuanLscript.py`: generate ECharts JavaScript files

### Purpose

`GuanLscript.py` combines the node and relationship fragments generated by `GuanL.py` into complete ECharts force-directed network scripts.

The script also performs formatting checks, including:

- removing UTF-8 BOM characters;
- cleaning extra commas;
- removing extra whitespace around quoted entity names;
- matching node and relationship fragment files by record number;
- reporting nodes that do not occur in any generated relationship.

### Usage

```bash
python GuanLscript.py \
  --gcgl1 /path/to/gcGL1 \
  --gcgl2 /path/to/gcGL2 \
  --output /path/to/gcscript
```

When `--output` is omitted, the default output directory is `gcscript` beside the supplied `gcGL1` directory.

### Output

```text
<record_id>.script.js
```

Each generated JavaScript file contains network nodes, relationships, entity categories, force-layout settings, labels, and draggable-network configuration. These files were designed to be embedded in MiREA website pages.

## 3. `details.py`: retrieve PubMed metadata and generate evidence fragments

### Purpose

`details.py` matches entity pairs to supporting PMIDs, retrieves PubMed metadata through NCBI Entrez, and generates HTML-table fragments for evidence detail pages.

### Required manually prepared input files

#### `Pmids.txt`

A three-column tab-delimited file without a header:

| Column | Content |
|---|---|
| 1 | Interaction ID |
| 2 | First entity |
| 3 | Second entity |

#### `detail.txt`

A four-column tab-delimited file without a header:

| Column | Content |
|---|---|
| 1 | First entity |
| 2 | Second entity |
| 3 | PMID |
| 4 | Supporting evidence sentence |

#### `id.txt`

A one-column list of interaction IDs for which detail pages should be generated. The original script reads this file using UTF-16 encoding.

### NCBI Entrez email

Before execution, replace the placeholder in `details.py` with a valid contact email:

```python
Entrez.email = "your_email@example.com"
```

### Usage

Run the script from a working directory containing `Pmids.txt`, `detail.txt`, and `id.txt`:

```bash
python details.py -d "Helicobacter pylori-induced gastric cancer"
```

The `-d` argument supplies the disease name displayed on the evidence page.

### Output

The script creates a `DT/` directory containing intermediate files and HTML-table fragments:

```text
DT/<interaction_id>.txt
DT/<interaction_id>.text
```

The generated evidence information includes PMID, disease, publication date, journal, article title, authors, and supporting evidence sentence.

## 4. `details_html.py`: generate complete evidence HTML pages

### Purpose

`details_html.py` inserts each `DT/*.text` evidence fragment into a manually prepared HTML template and generates a complete HTML detail page.

### Required template

The working directory must contain:

```text
html_gm.txt
```

The template must include this placeholder:

```text
****text****
```

### Expected working-directory layout

```text
working_directory/
├── html_gm.txt
├── DT/
│   ├── 1.text
│   ├── 2.text
│   └── ...
└── details/
```

The `details/` directory is created automatically if it does not exist.

### Usage

```bash
python details_html.py
```

### Output

```text
details/<interaction_id>.html
```

## Manual preparation statement

The following operations were performed manually during the original MiREA website construction:

1. arranging each disease-specific `data` table into the fixed nine-column `<prefix>GuanL.txt` format;
2. replacing empty interaction fields with `@`;
3. preparing `Pmids.txt`, `detail.txt`, and `id.txt` from the released `data` and `sp` tables;
4. preparing the `html_gm.txt` page template.

These were spreadsheet-assisted preparation steps and were not implemented as standalone scripts. Full disease-specific `data` and `sp` files are distributed separately through the project data repository.
